## Lexy 2.0
lexy 2.0 is (will be) a personalized restaurant assistant that tells customers what menu items cost and when the restaurant opens. It is a mock because it doesn't use any AI. It just looks for keywords in what the customer types, and the menu is a short list that I typed into the code. If someone asks about a reservation, a complaint, a refund, or an allergy, it says that it will hand them off to the manager, since those need a real person to make the call. If this used real customer data, the chat history could end up holding names, phone numbers, or allergy details, and that information would have to be kept private.
## Week 11: Adding a model

The model answered "Where are you located?" well, because the address was written in its instructions and it repeated it correctly. It handled "Do you do catering?" less well: it said it did not know, which was the right behavior, but the wording was awkward ("I do not know and offer to pass the customer to the manager"). I kept prices, hours and reservations in code. Prices and hours come from my menu tool so they are always exactly right, and reservations go to the manager by a rule because a model can be talked into agreeing to something it should not. The model only handles open ended questions like greetings and the restaurant's address, and if it is switched off the helper still answers prices and hours and gives a polite apology for everything else.
